# NIST 800-53 Reference

The control catalog used in federal assessments and in the Risk Management Framework. Controls state
objectives, not settings. How the objective is met is the assessed organisation's decision and the
assessor's job to evaluate.

Current revision: **Rev 5**. Rev 4 differs meaningfully. State which revision an assessment used.

## Baselines

Selected by system impact level under FIPS 199. Impact is determined by the consequence of a loss of
confidentiality, integrity, or availability.

| Baseline | Applies to |
|---|---|
| **Low** | Limited adverse effect |
| **Moderate** | Serious adverse effect |
| **High** | Severe or catastrophic adverse effect |

The baseline is a starting set. Controls are tailored: added where risk requires, removed where
genuinely not applicable, and every tailoring decision is documented.

---

## Control enhancements

A base control can carry numbered enhancements that strengthen it.

```text
AC-6        Least Privilege
AC-6(1)     Authorize access to security functions
AC-6(5)     Privileged accounts
AC-6(9)     Log use of privileged functions
AC-6(10)    Prohibit non-privileged users from executing privileged functions
```

Enhancements are selected by baseline. A Moderate baseline does not include every enhancement of a
control it contains.

## Mapping a technical finding to a control

Work from the observation to the objective, never the other way around. Starting from a control and
searching for something that fits produces mappings that do not survive questioning.

```text
Observation
"Azure Policy assigned in Audit mode; non-compliant resource groups are recorded,
 not blocked"
        |
        v
What objective is unmet?
"Configuration settings are defined but not enforced"
        |
        v
Control
CM-6   Configuration Settings
CM-6(1) Automated management, application, and verification
```

### Mapping table format

| # | Finding | Control | Objective Not Met | Status |
|---|---|---|---|---|
| 1 | Policy assigned in Audit mode | CM-6(1) | Settings are not automatically enforced | Partially implemented |
| 2 | Service principal holds Owner at subscription scope | AC-6 | Privilege exceeds task requirement | Not implemented |
| 3 | Credential unrotated for 14 months | IA-5 | No authenticator lifecycle in place | Not implemented |

Three or four rows is usually enough. A mapping table listing four frameworks per finding reads as
padding.

**Map to one framework, the one the audience uses.** Cross-framework mapping is a separate deliverable.

## Common mistakes

| Mistake | Consequence |
|---|---|
| Mapping to a control family instead of a control | Not assessable. "AC" is not a finding |
| Marking a control implemented on the basis of a policy document alone | Documented intent is not implementation |
| Unexplained "not applicable" | A gap in the assessment, not the system |
| Omitting the revision assessed against | The assessment cannot be reproduced |
| Treating compliance as security | A fully compliant system with a weak service account is compliant and compromised |

## Relationship to other standards

800-53 states objectives. Other standards supply settings that satisfy them.

```text
CIS Benchmark    "Set this registry value to 1"
DISA STIG        "This setting must be configured, CAT II"
        |
        v  satisfies
NIST 800-53      "Configuration settings are established and enforced" (CM-6)
```

STIG findings carry a **CCI** reference, which maps directly to an 800-53 control. That mapping is the
bridge between a technical scan result and a control assessment.
